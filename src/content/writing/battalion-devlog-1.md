Lately, I've been working on Battalion, a graph-based orchestrator for AI-assisted software development. The idea is to build not just human-in-the-loop, but human-enhanced-by-the-loop. I'm terrified of the thought that I'll forget how to write code the old-fashioned way in the AI era. So Battalion has come from this thought: **Humans design the software. AI writes the code. Both learn.**

This week's lesson: don't trust an AI's summary of its own work without checking it yourself.

I'd merged a CLI command (`battalion setup`) that an AI coding assistant (ChatGPT Codex) reported as complete and tested. Standard practice on this project is to independently verify every claim against the actual code rather than take the summary at face value, as it should be on every project.

Verification turned up a real bug: a placeholder value (`state.ticket_id`) had been left wired into a field that was supposed to hold actual spec text. It compiled, it ran, and the tests that existed didn't catch it because nobody had written a test that checked what was in that field, only that something was.

Small bug, but it's the kind of thing that's easy to miss when the summary telling you "it works" was generated by the same system that wrote the code. It's a big part of why Battalion treats verification as a distinct, structurally enforced step rather than a courtesy check.

More on the actual architecture in future posts. For now: trust, but verify. Especially when the thing doing the summarizing has an incentive to tell you it's done. Both the human and the AI can learn from a mistake like this.
